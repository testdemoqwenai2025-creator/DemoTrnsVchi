OTA Pipeline Infrastructure

How over-the-air updates are structured: cloud providers (AWS IoT / Azure IoT) vs a dedicated private vehicle registry. Hybrid is recommended for most AV deployments.

Honest scope. The OTA pipeline is NOT implemented in this UI. It is cloud/vehicle infrastructure. This page shows what the pipeline would look like to an operator.
☁ Cloud vs private vehicle registry
☁ AWS IoT Core + Jobs
Pros: Mature, global, signed bundles. Cons: Vendor lock-in, per-device cost. When: Startup / early fleet.
☁ Azure IoT Hub + Device Update
Pros: Same maturity, MS stack integration. Cons: Same lock-in. When: MS shop customers.
🗄 Private vehicle registry (self-hosted)
Pros: No per-device cost at scale, full data sovereignty. Cons: Build everything yourself. When: >10k vehicles / defence.
✅ Hybrid (cloud CDN + private HSM) Recommended
Pros: Best of both — cloud for distribution, private for signing. Cons: More moving parts. When: Most production AV deployments.

🛡 Safety constraints
  • No OTA while driving — vehicle must be parked, charging, or in depot
  • Battery must be above 30% for the update
  • Rollback must always be possible (A/B partition mandatory)
  • Update is never forced — safety-driver or operator can defer
  • Every update is logged in the audit trail — version, vehicle, timestamp, signing key, rollback if any
